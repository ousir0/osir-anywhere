# OSIR Client 本机模型绑定 v1

本文件说明现有 `schema.json` 的发布和读取约定，不增加字段、不改变云端 Runtime 配置。

- Client 先完成配置、模型目录与代理就绪，再原子发布 `available:true` 的描述符，最后发起 Anywhere handoff。首次安装期间可以先发布 `available:false`。
- 描述符目录由当前用户持有，POSIX 权限为 `0700`，文件为 `0600`；不经过软链接。Windows 使用已有文件句柄与 ACL 校验。
- `configSha256` 和 `catalogSha256` 对应实际文件的完整字节。更换配置、目录、默认模型、默认推理强度、模型清单或连接模式时，应一起更新描述符与 `revision`。
- 心跳只更新 `expiresAtMs`，保持 `revision` 和其余字段稳定。每次采样时有效期必须大于当前时间且不超过当前时间后 35 秒；Client 在运行期间持续续期。JSON 字段顺序不构成版本变化。
- 模型 `id` 使用发给 Codex 的完整标识，`defaultModel` 与原生配置的 `model` 完全一致，并且包含在 `models` 中。标题可以用于展示；Anywhere 不猜测裸模型名或移除供应商前缀。
- Anywhere 对两次有效采样比较除有效期外的全部描述符字段，对配置和目录仍逐字节校验 SHA。原子发布撞上描述符文件读取时，最多重新完整采样该描述符 3 次，权限和文件身份检查保持有效。
- 真正的 revision、路由变化或过期会使现有运行实例保持失效。恢复通过重新建立 Runtime 获得新绑定，不在旧实例内切换路由或重放消息。
- 已授权的 Desktop handoff 遇到尚不可用的 Codex 时，在现有 45 秒准备窗口内调用现有发现接口更新缓存；该接口也会恢复已保存的 active 实例。设备创建、实例创建和不确定结果的启动请求不循环重放。超时、取消和未知启动错误仍结束当前准备。

Client 不需要传递密钥、原生配置或消息正文；诊断只返回固定错误码与允许公开的模型字段。
